Running Games

NOTE: WinAGI is not an interpreter. You need to have a compatible interpreter (Sierra, NAGI, AGILE, etc.) available to your game files in order to use the Run game feature.

You can run your game to test it by using the Run command in the Game menu. This feature only works if you have selected a platform on the Game Properties dialog. Currently, WinAGI supports the use of the following interpreters:

DosBox: DosBox is not an interpreter, but with it, you can run your game using an original Sierra MSDOS interpreter. When you select this option, you will need to designate the actual DOS executable file to run in DosBox (usually a loader file such as 'sierra.com', or an unencrypted interpreter 'agi.exe' file). WinAGI will automatically include the correct command line parameter to run the game in the current game directory. Please note that you must have a Sierra MSDOS interpreter with all required support files to run your game in DOSBox.

ScummVM: If you have ScummVM version 2026.4.0 or later installed, you can configure WinAGI to use it to run your game during testing. WinAGI will automatically include the correct command line parameter to run your game.

Keep in mind that ScummVM has an aggressive game detection system that may complain if a game's GameID matches a Sierra game but the games resource files don't match a known Sierra release. In this case ScummVM may refuse to run the game. You can work around this by changing the GameID property to a non-Sierra game.

AGILE: AGILE is an AGI engine written in C# by Lance Ewing. WinAGI can be configured to run AGILE. It must be the stand alone app; it will not run if you are using the browser version of AGILE.

NAGI: You can use NAGI to run a game during testing, but it is not as flexible as other platforms. NAGI will only run correctly if the NAGI program files are actually located in the game directory. Also, NAGI does not accept command line options, so that field is disabled when NAGI is selected.

The WinAGI compatible fork of NAGI includes support for all extended characters as well as custom font files if needed for non-standard code pages. It also includes support for customized palettes.

If you have an emulator platform other than one of these, use the 'Other' option. It will be up to you to manually enter the correct information in the Command Line Options field in order to correctly run your game.

Keep in mind that the selected platform will use the compiled logics that are currently in your VOL files; if any of your logic source files need to be compiled, you will have the option to compile the changed logics before the game is run.
